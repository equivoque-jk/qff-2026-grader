# 운영진: 제출 수집과 일괄 재채점

참가자는 문제지의 TODO를 작성한 뒤 모든 셀을 실행합니다. 마지막 셀은 답안을 한 번 수집해 채점하고, 같은 답안 JSON과 점수표를 담은 제출 ZIP을 생성합니다. Colab은 브라우저에 자동 다운로드를 요청하고, Jupyter에서는 출력된 다운로드 링크를 누릅니다. VS Code에서는 출력에 표시된 경로에 ZIP이 로컬 파일로 저장됩니다. 제출 접수는 행사에서 안내한 제출처를 통해 진행합니다.

운영진은 행사에서 정한 제출처로 **제출 ZIP과 작성한 `.ipynb`를 함께** 받습니다. 제출처·마감 시각·제출 단위·파일명 규칙·문의 채널은 행사 공지에 따릅니다. 제출처의 계정·접수 시각을 기준으로 제출자의 신원과 기한 준수 여부를 확인하세요. ZIP에 있는 팀 ID, 생성 시각, 실행 ID는 참가자가 수정할 수 있는 메타데이터입니다. 해시는 파일 간 일치 확인용이며 제출자 인증이나 접수증이 아닙니다.

## 설치

Python 3.10–3.13 환경에 [Grader 2.0.4](https://github.com/equivoque-jk/qff-2026-grader/releases/tag/v2.0.4)를 설치합니다. 로컬 권장 버전은 Python 3.12입니다. 아래 URL은 참가자용 문제지가 설치하는 패키지와 같은 파일을 가리킵니다. 파일의 SHA-256은 같은 Release의 `SHA256SUMS.txt`에서 확인할 수 있습니다. 운영진 재채점만 할 때는 시뮬레이션·시각화 도구를 위한 `[notebook]` 옵션이 필요하지 않습니다.

```sh
python -m pip install "https://github.com/equivoque-jk/qff-2026-grader/releases/download/v2.0.4/qff_local_grader-2.0.4-py3-none-any.whl"
qff-grade-batch --version
```

## 참가자 실행 안내

참가자에게 [공식 문제지 저장소](https://github.com/equivoque-jk/qff-2026-Challenge-Quiz)의 **`QFF_Challenge_Colab.ipynb`**를 안내합니다. 문제 설명, 이미지, 실험 코드와 설치 셀이 이 파일에 들어 있으며 준비 A가 Grader 2.0.4를 자동으로 설치합니다.

1. 준비 A를 먼저 실행하고 설치 완료를 확인합니다.
2. 재시작 안내가 나오면 Colab에서는 **런타임 → 세션 다시 시작**, VS Code·Jupyter에서는 **커널 재시작** 후 준비 A를 다시 실행합니다.
3. 준비 B·C·D와 해당 문제에 필요한 셀을 순서대로 실행하며 TODO를 작성합니다.
4. 답안 전체를 채점하고 제출 ZIP을 만들 때 **모두 실행 / Run All**을 선택합니다.

세션이나 커널을 재시작하면 이전 변수와 함수 정의가 사라집니다. 화면에 출력이 남아 있어도 필요한 셀은 다시 실행해야 합니다. 설치 과정에서 안내하는 재시작은 Colab 런타임 삭제와 다르며, 런타임을 삭제하면 설치된 패키지도 다시 설치해야 할 수 있습니다.

## 여러 제출 재채점

받은 ZIP을 `received/` 폴더에 모으고 실행합니다. 이름이 같은 파일은 제출자별 하위 폴더에 두면 됩니다. 결과 폴더는 입력 폴더 밖으로 지정하세요.

```sh
qff-grade-batch received --output grading_results
```

입력 폴더 아래의 `.zip`과 `.json`을 재귀적으로 찾습니다. `result.json`, `manifest.json`, `latest.json`, `summary.json`, `audit.json`, `*_result.json`은 제외합니다. 완성한 `.ipynb`는 함께 보관할 수 있으며 재채점기가 실행하지 않습니다. **제출 ZIP과 그 ZIP에서 추출한 JSON을 둘 다 넣으면 별개 제출 두 건으로 처리하므로 한 형식만 넣으세요.**

한 번에 최대 1,000개를 처리합니다. ZIP은 압축 상태 16 MiB, 내부 파일 합계 32 MiB 이하이며 루트에 `submission.json`, `result.json`, `result.csv`, `manifest.json`만 허용합니다. JSON만 제출받은 경우도 처리할 수 있지만 팀 메타데이터는 비어 있습니다.

실행마다 UTC 시각과 임의 ID로 새 결과 폴더가 만들어집니다. 이전 채점 기록은 덮어쓰지 않습니다.

```text
grading_results/
  <UTC 시각>-<실행 ID>/
    scores.csv
    summary.json
    0001/
      submission.json
      result.json
      audit.json
    0002/
      ...
```

- `scores.csv`: 제출 파일마다 한 행. 기본 100점·추가 20점·합계, 판정, 입력 파일 경로, 답안 SHA-256, 진단, 상세 결과 경로를 기록합니다. Excel용 UTF-8 BOM을 사용하며 참가자 입력이 수식으로 해석되지 않도록 처리합니다.
- `summary.json`: 같은 배치의 전체 행과 판정별 건수입니다.
- `0001/submission.json`: 실제 재채점한 답안 바이트를 보존합니다. ZIP 구조 자체가 잘못되어 답안을 읽지 못한 경우에는 생성되지 않습니다.
- `0001/result.json`: 운영진 환경에서 새로 계산한 점수와 문항별 진단입니다.
- `0001/audit.json`: 원본 상대 경로, 답안 해시, 신뢰하지 않은 참가자 메타데이터, 메타데이터 이상 여부입니다.

참가자가 ZIP에 넣은 `result.json`과 `result.csv`의 점수는 사용하지 않습니다. `submission.json`의 반환값·회로 데이터만 같은 고정 배점으로 재채점합니다. manifest에 적힌 답안 해시가 실제와 다르면 점수표에 경고를 남기며, 실제 받은 답안 자체는 재채점합니다.

잘못된 ZIP이나 JSON이 있더라도 다음 파일을 계속 처리합니다. 압축 데이터가 손상되거나 잘려 읽을 수 없는 ZIP도 해당 제출만 `invalid` / `RECEIVED_FILE_INVALID`로 기록합니다. 입력 파일 전체를 읽을 수 없거나 채점 프로세스가 실패한 건은 점수를 빈칸으로 남깁니다. 문항별 잘못된 답안에는 [배점표](SCORING.md)의 부분 점수 규칙이 적용됩니다. 오류를 임의로 0점 또는 정상 채점으로 간주하지 말고 상세 진단을 확인하세요.

종료 코드는 모두 정답 0, 오답·미완성 포함 1, 입력 오류 포함 2, 채점 실행 오류 포함 3입니다. 1은 배치 실행 자체의 실패를 뜻하지 않습니다. 결과 파일을 저장하지 못하는 등 배치 준비·저장 실패는 2를 반환하며 표준 오류에 이유를 출력합니다.

## 공식 성적 선정

일괄 재채점기는 **받은 시도 전체**를 내보냅니다. 참가자가 적은 시각이나 점수로 최신 제출·최고점·공식 팀 신원을 자동 선정하지 않습니다. 운영진은 제출처의 접수 기록과 행사 공지의 선정 기준에 따라 공식 성적에 반영할 제출을 고른 뒤, 해당 행의 재채점 점수를 사용합니다.

실행별 점수 또는 문항별 최고점을 합치는 기능은 없습니다. 선행 회로에 의존하는 문항이 있으므로 문항별로 서로 다른 답안의 최고점을 조합하지 마세요. 채점 프로세스 실패 건은 원인을 해결하고 같은 JSON을 다시 채점한 뒤 운영진 기록에서 대체 결과를 지정합니다.

제출된 노트북은 풀이 과정 확인용으로 함께 보관합니다. 반환값 채점은 코드가 어떤 방식으로 계산됐는지까지 증명하지 않으며, 재채점기는 참가자 코드를 실행하지 않습니다. 노트북 실행을 통한 별도 검토가 필요하면 운영진의 개인 환경에서 무심코 실행하지 말고 검토 환경을 분리해 진행하세요.

답안 JSON 하나를 재채점할 때는 다음 명령을 사용합니다.

```sh
qff-grade submission.json --output result.json --csv result.csv
```

이 명령은 JSON을 입력받습니다. ZIP을 직접 처리하려면 위의 `qff-grade-batch`를 사용하세요.
